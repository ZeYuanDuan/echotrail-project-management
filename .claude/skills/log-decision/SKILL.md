# log-decision

在 `EchoTrail-DECISIONS.md` 的〈一、決策紀錄（依時間序）〉補一筆決策，格式對齊現有條目：**決定了什麼、為什麼、考慮過哪些方案、誰在什麼場合拍板、連帶效應**。

## 這個 skill 只負責

`EchoTrail-DECISIONS.md` 的內容（決策紀錄 + 開放問題兩區）。
**不碰** SPEC 的規格文字——如果這個決策改動了 SPEC 裡「已定案」的內容，SPEC 要另外改，跟本次一起走 `推 spec`（push-spec）開同一個 PR。
CHANGELOG 由 `log-changelog` 另外記。

## 步驟

1. 確認 repo：`git remote get-url origin` 要是 `echotrail-spec`。不是就停下。

2. 讀 `EchoTrail-DECISIONS.md`，掌握現有結構：
   - 〈一、決策紀錄〉：`### YYMMDD　標題` 的日期區塊，內含 bullet 與 **粗體小標**
   - 〈二、目前未決事項〉：四個分類（🚩 分歧待開會 / 待技術評估 / 待補充規格細節 / 待 team 確認非阻塞），**編號**條列

3. 從對話或詢問使用者，收集：
   - **決策內容**：具體決定了什麼
   - **理由**：為什麼這樣決定
   - **考慮過的其他方案 / 被推翻的舊定案**：有的話寫出來（推翻舊定案要註明原本是哪天定的）
   - **對應 SPEC 章節**：`A-4`、`B-2`、`C-7`… 或「非章節性」
   - **拍板者與場合**：team 討論 / Webber / Ariel / 使用者提供 Figma 佐證 …
   - **是否解掉了〈二〉的某個開放問題**：第幾題
   - **連帶效應**：有沒有牽動其他章節的編號、交叉引用、SPEC 文字

4. 寫進〈一、決策紀錄〉：
   - 今天日期換算成 `YYMMDD`（例：2026-09-04 → `260904`）
   - 已有 `### 260904　…` 區塊 → 在該區塊內容最後補 bullet
   - 沒有 → 在〈一〉的最後、`---`（與〈二〉之間那條）**之前**，新增 `### 260904　<簡短標題>` 區塊
   - 條目風格照現有的來：一句開場 bullet，關鍵決策用 `**粗體小標**` 起頭，理由／方案／連帶效應用子 bullet

5. 如果解掉了〈二〉的開放問題：
   - 在該題原地改成：`~~<原題號與題目>~~ ✅ **260904 定案**：<一句結論>，見〈一、決策紀錄〉260904。`
   - 保留題號不要重新編號（其他地方可能用「第X項」引用）
   - `grep` 一下該題號在檔案其他地方有沒有被引用（「見開放問題第X項」之類），有的話一起更新指向
   - 若使用者明確要求「清乾淨」才整段刪除，並提醒編號引用可能要順手修

6. `git --no-pager diff EchoTrail-DECISIONS.md` 秀給使用者確認。

7. 收尾：
   - 這個決策若改動 SPEC 已定案內容 → 提醒把 SPEC 一起改，同一個 PR
   - 提醒用 `記 changelog`（log-changelog）補一句摘要
   - 全部改完用 `推 spec`（push-spec）開 PR，reviewer 指定另一位 PM

## 寫作風格

繁中，對齊現有條目的密度與語氣：具體、帶日期脈絡、講清楚「推翻了什麼 / 帶動了什麼」。不要只寫結論不寫理由。
