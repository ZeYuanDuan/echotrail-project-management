## Function Detail

### D．對話人設與互動流程（延伸 A-2冷啟動對話）

D 組負責使用者跟 AI 教練「艾可」對話、深挖單一事件，最終收斂成一張 Echo Card 的互動流程。不負責 Echo Card 產出後的呈現（那是 E 組職責），也不負責把多張事件卡批次收集成時間軸（那是既有 A-2／A-3 的職責）。

---

#### D-1　AI 教練人設與三段式回應結構

👤 **User Story**
As a 想聊職涯困擾的使用者
I want AI 用有陪伴感、但精準指出我話裡具體矛盾或模式的方式回應，而不是空泛安慰
So that 我覺得對方真的有在理解我，而不是在套話術

**功能概述**：具名 AI 教練「艾可」，語氣親切但不說「聽起來很累」這類空泛安慰句，每次回應固定遵循三段式結構：同理（具體引用對方原話）→ 輕量分析（指出模式／矛盾）→ 延伸引導（拋一個問題或邀請）。

- 「具體引用對方原話」是硬性要求，不可用通用句型帶過
- 每輪對話 AI 只回應一次，不追問第二題（跟 A-2 每輪僅問一題的原則一致）
- 🟡 待確認：三段式結構要靠單一 prompt template 產出，還是需要拆成多步驟（分析→生成）？跟 MVP-SPEC「Process 採輕量 AI prompt，非完整自動化引擎」的原則是否一致？

#### D-2　單一事件深挖對話的收斂邏輯

👤 **User Story**
As a 已經針對一件事聊了幾輪的使用者
I want 系統知道什麼時候該收斂，並主動邀請我產出這次的 Echo Card
So that 我不用自己判斷什麼時候該停

**功能概述**：針對單一事件的深挖對話，達到收斂條件後由 AI 在回覆中主動邀請使用者點擊〈Generate Insight〉，或使用者也可以隨時主動輸入「Please generate my insight」跳過剩餘輪次。

- demo 腳本固定為 3 輪對話後邀請收斂，正式產品需要定義判斷收斂的規則（例如：是否已經同時收集到「事件內容／情緒／使用者的價值判斷」三個面向）
- 使用者若不滿意 AI 的分析，直接在輸入框繼續打字延伸即可，不提供「重新輸入討論」這類額外按鈕
- 🟡 **待確認（重要）**：既有 MVP-SPEC A-2 定義的是「收滿 3-5 張事件卡才自動結束」的**批次對話**；這份腳本描述的是「針對單一事件深挖 3 輪後產出 1 張 Echo Card」的**單事件對話**。這是兩種並存的對話模式（例如 A-2 是快速掃過多個事件、D-2 是使用者主動選一個事件深聊），還是這份腳本其實是把 A-2 其中一輪具體化？需要 team 對齊，否則 A 組跟 D 組的資料結構會對不起來。

### E．Echo Card 呈現規格（對應 B-3逐事件洞察的 UI 呈現）

E 組負責把 D 組收斂完成的單一事件對話，轉成一張結構化卡片呈現給使用者確認，並計算這次事件跟使用者既有 Persona 資料庫的匹配程度。不負責產出跨事件的整體洞察（那是既有 B-4 的職責）。

---

#### E-1　Echo Card 版面與欄位

👤 **User Story**
As a 完成一輪對話深挖的使用者
I want 看到系統把這次對話整理成一張結構化卡片
So that 我一眼就能看懂這次談的事件被拆解成哪些面向，而不是一長串文字

**功能概述**：兩欄 wireframe 排版，六個固定欄位：事件的發生／我的情緒／我在意·適合·擅長／我討厭·不適合·不在意／我的價值主張／和過去的我是否匹配（見 E-2）。視覺風格須與 Dashboard 頁面一致，不是獨立配色系統。

- **明確規則**：「我在意/適合/擅長」與「我討厭/不適合/不在意」兩格內容**不可互為邏輯負命題**，必須各自指向不同維度（例如一個講「決策方式」、一個講「對環境資源狀態的容忍度」）——這條規則要變成產出 Echo Card 的 LLM prompt 裡明確的禁止指令，不能只靠人工事後檢查
- 「我的價值主張」欄位須附上一句逐字引用的使用者原話作為佐證
- 🟡 **待確認**：Echo Card 的六個欄位，跟既有 MVP-SPEC B-3 定義的洞察資料結構（洞察文字／客觀證據／主觀證據）要怎麼對應？是 Echo Card 六格取代 B-3 的三欄位資料結構，還是 Echo Card 是在 B-3 資料結構之上的一種排版呈現？這會影響後端資料 schema 怎麼設計。

#### E-2　匹配分數機制（和過去的我是否匹配）

👤 **User Story**
As a 產出一張新 Echo Card 的使用者
I want 看到這次的體悟跟我過去累積的 Persona 資料庫比對後的相似程度
So that 我知道這是延續我原本的樣子，還是出現了值得留意的新訊號

**功能概述**：Echo Card 內一個獨立標示的特殊格，顯示 0-100 分的匹配分數＋文字判讀（例如「部分符合」）＋至少各一條「符合關鍵字對照」（綠色 ✓）與「落差關鍵字對照」（紅色 ⚠），每條對照都要寫出「本輪講的是什麼」對比「既有 Persona 資料庫裡對應的是什麼」。

- demo 腳本固定值為 78 分／部分符合，正式產品需要定義計算方式
- 🟡 **待確認**：匹配分數的計算邏輯是什麼？（語意相似度／LLM 自評／關鍵字重疊率？）分數區間對應的文字判讀門檻（例如幾分以上算「高度符合」、幾分以下算「落差明顯」）目前完全未定義，需要跟 B-3「內部信心分數」的機制對照，避免做出兩套邏輯不一致的信心分數系統。

### F．My Dashboard 完整規格（擴充 C-1能力傾向儀表板）

F 組負責在既有 C-1 能力傾向排行之外，把使用者累積的事件資料整合成完整的自我畫像。與 B 組的差異維持既有原則：B 是針對「過去發生的事」做整理歸納，F／C 是針對「這個人展現過的能力／傾向」做輕量畫像。

---

#### F-1　我的 Persona 摘要卡

👤 **User Story**
As a 已經累積數則事件的使用者
I want 看到系統從我所有事件裡歸納出的一句話人物摘要
So that 我能快速掌握目前系統怎麼理解我，而不用自己重新讀一遍所有事件

**功能概述**：Dashboard 左側一張獨立卡片，包含：一句話引言式摘要、3 點條列說明、代表事件標籤（連結回具體事件＋原句引用）、高頻關鍵字 pill 標籤。

- 引言句與條列須為 LLM 依據使用者所有已累積事件生成，非固定模板套字
- 代表事件標籤須可連結回時間軸對應節點（銜接既有 B-2 的錨點機制）
- 🟡 待確認：這張卡片就是原 MVP-SPEC Part 2 排除清單裡的「Persona自我畫像卡」，需要 team 明確決議是否排入本輪範圍（見文件開頭範圍衝突說明）

👤 **User Story**
As a 想更深入理解自己驅動力的使用者

### G．Dashboard 增量更新規則（新增，跨功能規則）

G 組定義的規則橫跨 E（Echo Card）與 F（Dashboard 各子模組），不是獨立畫面功能，而是「新 Echo Card 更新進 Dashboard 時」所有子模組都要遵守的共同行為。

---

#### G-1　只增不改、不刪的更新原則

👤 **User Story**
As a 已經累積一份 Dashboard 資料的使用者
I want 新的 Echo Card 更新 Dashboard 時，舊資料不會被覆蓋或刪除，只有明確標示出來的新增內容
So that 我不會覺得系統把我過去建立的自我認識直接抹掉重寫

**功能概述**：核心原則——不因為一個新事件就大改整個 Dashboard，只增補、不刪除、不覆寫舊內容。所有新增或變動的欄位加上綠色圓角小標籤「NEW」（非 emoji，pill 樣式），並觸發一次淡黃色背景閃爍動畫提示使用者「這是新的」。
